# CoordGen port plan

Goal: `rdoxide.Chem.rdCoordGen` (`AddCoords`, `CoordGenParams`, `SetDefaultTemplateFileDir`, the
`SetCoordMap`/`SetTemplateMol`/`minimizerPrecision` parameters, `useCoordGen` in `Compute2DCoords`) identical to RDKit
2026.09.1, which builds coordgenlibs 3.0.2 (BSD 3-clause, Schrödinger, Inc.; tarball
`https://github.com/schrodinger/coordgenlibs/archive/refs/tags/v3.0.2.tar.gz`, MD5 `bc9dabbbb2b99ae426f3a1bf16c4d3cc`).

## Source inventory (C++ lines)

| file | lines | role |
|---|---|---|
| `sketcherMinimizer.cpp` | 3750 | driver: fragments, scoring, placing, residues (the residue/protein part is unused by RDKit) |
| `CoordgenTemplates.cpp` | 4874 | autogenerated ring-system templates (data, converted by script) |
| `CoordgenMinimizer.cpp` | 1696 | force-field minimization, clash scoring, conformer search |
| `sketcherMinimizerAtom.cpp` | 1681 | atom model, stereo, CIP-like priorities |
| `CoordgenMacrocycleBuilder.cpp` | 1389 | macrocycle placement (dynamic programming over hex coordinates) |
| `CoordgenFragmentBuilder.cpp` | 1091 | ring system / chain placement |
| `sketcherMinimizerFragment.cpp`, `CoordgenFragmenter.cpp`, `...Molecule`, `...Bond`, `...Ring`, `...MarchingSquares`, headers | ~3k | model classes |

About 10k lines of logic plus the template data. The RDKit wrapper (`External/CoordGen/CoordGen.h`) converts an `ROMol`
into `sketcherMinimizerMolecule`, runs `runGenerateCoordinates` and copies the coordinates back; only that path is needed.

## Properties that make a bit-exact port feasible

* No random numbers (`grep rand` finds only comments). Pointer-keyed `std::set`/`std::map` are used for membership and
  lookup; every place that iterates them has to be checked for order dependence while porting.
* `float` arithmetic (`sketcherMinimizerPointF`, energies): reproduce C++ `float` semantics (f32 storage, f32 operators,
  `std::sqrt`/`atan2` float overloads) and build the oracle with `-ffp-contract=off`.
* The oracle is the official wheel (`rdkit.Chem.rdCoordGen`) plus, for traces, a C++ build of coordgenlibs from the tarball.
* The Maestro reader (maeparser) is only used for user supplied template files; the default templates are compiled in.

## Progress

* CG1a `external::coordgen::maths` (`sketcherMinimizerMaths.h`: `PointF` with the C++ `float`/`double` mixing, segment
  intersection, angles, projections, tridiagonal/cyclic solvers, closed Bezier control points, 3D helpers, cannon ball
  distance). 7998 calls with pseudo random input are bit-identical to the C++ header
  (`tests/data/coordgen_maths.txt`, driver `tools/coordgen_drv/maths.cpp`, built with `-ffp-contract=off`); the four
  functions using `acos`/`atan2` are compared to 2e-6 relative because the platform libm may differ in the last bit.
* CG1b `external::coordgen::model`: the arena model (`Model` owning atoms, bonds, rings, molecules; objects refer to each
  other by index) with atom (`findHsNumber`, `shareARing`, `canBeChiral`, `clockwiseOrderedNeighbors`, addition
  vectors, `getSubmolecule`, `mirrorCoordinates`), bond (`isStereo`, `isInterFragment`, `flip`, ring tests), ring
  (`isBenzene`, `isAromatic`, `contains`) and molecule (`forceUpdateStruct`, the SSSR ring search, bounding box)
  methods. 68 molecules (hetero, fused, spiro, bridged, macrocycles, ions) give the same lists, ring bond/atom order,
  flags, coordinates and flips as the C++ classes (`tests/data/coordgen_model.txt`, drivers `tools/coordgen_drv/`,
  `tools/make_coordgen_model_corpus.py`). The CIP ranking (`CIPAtom`, `setCIPPriorities`), the chirality info and the
  residue classes follow with the stereo stage; ties in `clockwiseOrderedNeighbors` use the atom index where C++ compares
  pointers.
* CG2 `external::coordgen::{fragment,fragmenter}`: `sketcherMinimizerFragment` data (no degrees of freedom yet) and
  `CoordgenFragmenter` (rigid fragments, ring/bond information, fixed/constrained flags, main fragment by the eight-step
  priority, long chains taking over the main fragment, parent/child tree with bond swaps, breadth first fragment order,
  flip info). 108 molecules (ring systems with alkyl chains of the length around every threshold, macrocycles, fixed and
  constrained atoms; the driver aborts on several unbonded atoms, so molecules are split into components as the sketcher
  does) give identical fragment lists, trees and bond directions (`tests/data/coordgen_frag.txt`,
  `tools/coordgen_drv/frag.cpp`, `tools/make_coordgen_frag_corpus.py`).
* CG3a `external::coordgen::templates`: the 82 built-in ring system templates (`data/templates.txt`, converted from
  `CoordgenTemplates.cpp` by `tools/gen_coordgen_templates.py`, coordinates rounded and normalized to bond length 1 as
  `normalizeTemplate` does), `morganScores`, the template matching `compare`/`checkIdentity` (molecule atom -> template atom
  mapping), and the 2x2 `svd`/`alignmentMatrix`. Templates and Morgan scores are bit-identical to the C++ code; 116 molecules
  (76 of the 82 templates with permuted/rotated/mirrored atoms, plus polycyclic RDKit molecules) give the same scores,
  first matching template, mapping and alignment matrix (`tests/data/coordgen_templates.txt`, `tools/coordgen_drv/tmpl.cpp`,
  `tools/make_coordgen_templates_corpus.py`). Not yet: the double bond stereo check inside `compare` for macrocycle double
  bonds (needs the CIP ranking; `unimplemented!` until the stereo stage), and the user template file (maeparser).
* CG3b `external::coordgen::cip`: the stereo code of `sketcherMinimizerAtom`/`Bond`: `CIPAtom` comparison (scores, medals,
  friends mask), `CIPPriority`, `setCIPPriorities`, `orderAtomPriorities`, `readStereochemistry`, `writeStereoChemistry`,
  `getRelativeStereo`, `setAbsoluteStereoFromChiralityInfo`, the three-atom `sameRing`, and the bond first-neighbour /
  Z-E helpers. Temporary dummy H / lone pair atoms are pushed to the arena and truncated afterwards. 58 stereo molecules
  (R/S centres, N/S/P centres, ring chirality, E/Z, macrocycle double bonds) give identical priorities, read results, written
  wedges and first neighbours (`tests/data/coordgen_cip.txt`, `tools/coordgen_drv/cip.cpp`,
  `tools/make_coordgen_cip_corpus.py`). The macrocycle double bond check in the template `compare` now uses it (template
  corpus regenerated without the macrocycle filter).
* CG4a `external::coordgen::fragment_builder`: `CoordgenFragmentBuilder` for fragments without macrocycles: fused ring
  information, side/central ring split, template lookup, ring placement (single, one-atom/bond fusion, two-or-more atom
  fusion with mirror choice), non-ring atoms by breadth first search with ZE inversion avoidance, DOF creation
  (`Fragment` constructor DOFs, scale-atoms, invert-bond), `avoidInternalClashes`, `storeCoordinateInformation`,
  `rotateMainFragment`. 108 molecules (7 skipped: macrocycles / non-planar systems) give identical coordinates, ring flags,
  DOF lists and fragment-local coordinates (`tests/data/coordgen_fbuild.txt`, `tools/coordgen_drv/fbuild.cpp`,
  `tools/make_coordgen_fbuild_corpus.py`). `unimplemented!`: the macrocycle builder and `checkForClashes`. Known gaps in
  the corpus: only one templated fragment, and the gap-scaling of ring-atom neighbours (`gap > PI`) is not exercised.
* CG5a `external::coordgen::minimizer`: the force field of `CoordgenMinimizer`: stretch, bend, clash, constraint and E/Z
  constraint interactions, the clash/stretch/bend/chiral-inversion interactions of a molecule (macrocycle bend rules
  included), `applyForces`, `run` (upstream never restores the lowest-energy coordinates because its running minimum is
  never updated; replicated) and `minimizeMolecule`. 72 molecules with randomly displaced coordinates (incl. macrocycles
  and E/Z) give bit-identical interaction counts, energies and final coordinates on macOS; the test allows 1e-3 relative
  for the platform `acos`. Not yet: `scoreClashes`/`scoreCrossBonds`, `avoidClashes*`, `checkForClashes`, conformer search,
  peptide constraints (residues). (`tests/data/coordgen_minim.txt`, `tools/coordgen_drv/minim.cpp`,
  `tools/make_coordgen_minim_corpus.py`.)
* CG5b `external::coordgen::{dofs,clashes}`: fragment degrees of freedom (flip, change parent bond length, rotate, scale
  atoms, invert bond: states, `apply`, penalties), `Fragment::setCoordinates`, `buildMoleculeFromFragments` with
  `alignWithParentDirection` (constrained and unconstrained), clash scoring (`scoreClashes`, crossing bonds, atoms inside
  rings, DOF penalties), `checkForClashes`, `avoidTerminalClashes`, the DOF search (`flipFragments`, `runSearch`,
  `growSolutions`; ordered maps give upstream's iteration order), the peptide backbone constraints, `avoidClashesOfMolecule`
  and `avoidClashes`. 108 molecules (101 with a non-macrocycle layout; 60 need the full search and minimization) give
  the same clean-pose flag, clash energy and final coordinates as the C++ code (`tests/data/coordgen_clash.txt`,
  `tools/coordgen_drv/clash.cpp`, `tools/make_coordgen_clash_corpus.py`). Deliberate difference: sets and maps keyed by pointer
  upstream use atom index order. `checkForClashes` is available but its caller in the fragment builder (atoms flagged
  `needsCheckForClashes`) now calls it (CG6b). Corpus gap: the atoms-inside-rings term is not exercised.
* CG6a `external::coordgen::driver`: the `sketcherMinimizer` pipeline as RDKit's `CoordGen::addCoords` uses it:
  canonical ordering (Morgan scores), splitting into molecules, cross-atom flags, fragment initialization (number of
  children atoms, longest chain), `buildFromFragments`, `avoidClashes`, `bestRotation`, `maybeFlip`, arranging several
  molecules (grid search for counterions and salts), `assignPseudoZ`, `runGenerateCoordinates`. RDKit passes no atom
  chirality, only double bond stereo. 68 molecules (salts, mixtures, E/Z, fused and bridged rings; no macrocycles) give
  the same coordinates as the C++ library (`tests/data/coordgen_sketch.txt`, `tools/coordgen_drv/sketch.cpp`,
  `tools/make_coordgen_sketch_corpus.py`); molecules that need the macrocycle builder are skipped in the test (it counts
  them). Not ported: residue/protein layouts, proximity relations (zero order bonds), the Maestro reader. Next: the
  macrocycle builder, then `AddCoords` (scaling, centring, coordinate maps, template molecules) and the Python module.
* CG6b `external::coordgen::polyomino`, `external::coordgen::macrocycle`: `CoordgenMacrocycleBuilder`. Rings of nine or more
  atoms are laid out on the contour of a polyomino (hexagon lattice: skewed, ragged and round shapes, pentagon corners for
  odd sizes) chosen by double bond (cis/trans) and fused ring constraints plus heteroatom and substituent restraints;
  when no shape fits the ring is opened at a bond (`findBondToOpen`), laid out by a nested sketcher with minimization
  skipped (`openCycleAndGenerateCoords`; the nested sketcher is a second `Model`, `Minimizer::skip_minimization` and
  `Model::force_open_macrocycles`) and pulled closed by a stretch interaction (`avoidClashesOfMolecule` takes extra
  interactions). `newScorePlanarity` and the fragment builder use it. 130 macrocycles (crown ethers, cyclic peptides,
  macrolides, E/Z polyenes, fused and bridged; 8+ take the open-ring fallback) give the same coordinates as the C++
  library (`tests/data/coordgen_macro.txt`, `tools/make_coordgen_macro_corpus.py`, driver `sketch.cpp`).
  Upstream quirk kept: `scorePathRestraints` indexes the path with the position in the list of substituted atoms.
  Corpus gap: perturbing the restraint weights (heteroatom, substituent clash) does not change any result, so those
  constants are not verified by the corpus. Next: `AddCoords` (scaling, centring, coordinate maps, template molecules)
  and the Python module.
* CG7a `external::coordgen::add_coords`: RDKit's `CoordGen::addCoords` and `CoordGenParams` (scaling 50, precision 0.01,
  coordinate maps and template molecules as constrained atoms, double bond stereo only, centring when there is no map or
  template). 86 of 87 molecules (plain, with coordMap, with template molecule) equal the RDKit wheel's `rdCoordGen.AddCoords`
  (`tests/data/coordgen_addcoords.txt`, `tools/make_coordgen_addcoords_corpus.py`). Ibuprofen differs: its minimization ends
  unclean and the wheel ends in another state, while the oracle driver built without floating point contraction agrees
  exactly with this port. `treatNonterminalBondsToMetalAsZeroOrder` is rejected. Next: the Python module `rdCoordGen`,
  `Compute2DCoords(useCoordGen)`, the ratchet.
* CG7b `rdoxide.Chem.rdCoordGen` (`AddCoords`, `CoordGenParams`, `SetDefaultTemplateFileDir`), `rdDepictor.IsCoordGenSupportAvailable`
  (true), `SetPreferCoordGen`/`GetPreferCoordGen`/`UsingCoordGen`, and `Compute2DCoords` going through CoordGen when it is
  preferred and `forceRDKit` is not set. Upstream `External/CoordGen/Wrap/testCoordGen.py` (4 tests) and
  `testUsingCoordGenCtxtMgr` now pass and are in the ratchet; the full ratchet shows no regression. Not ported: the Mae
  template reader (`SetDefaultTemplateFileDir` is accepted and ignored: the templates are built in).
