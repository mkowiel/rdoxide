# pubchem_shape (`rdkit.Chem.rdShapeAlign`) port

RDKit's `External/pubchem_shape` wraps NCBI's pubchem-align3d (commit daefab3, public domain, ~2000 lines of float code;
`exp` is `expApproxDouble`, the lookup tables are unused) in `PubChemShape.cpp` (766 lines) and `Wrap/cshapealign.cpp`.
It is independent of the newer `rdGaussianShape` already ported (stage 45): the scores differ (upstream `test_rdshapealign.py`
expects 0.773/0.305 for `test1.sdf`; `rdGaussianShape.AlignMol` gives other numbers), so it needs its own port.

| step | content | oracle |
|---|---|---|
| S1 `external::pubchem_shape::functions` | `shape_functions1/2.cpp`: Gaussian alphas, overlaps and analytic gradients, quaternion/matrix algebra, steric frame (eigen decomposition), colour type sets | C++ driver built from the NCBI sources, hex floats |
| S2 `neighbor` | `shape_neighbor.cpp`: `Neighbor_Conformers` (starting points, two-phase BFGS-like optimization) | same driver |
| S3 `ShapeInput`, `PrepareConformer`, `AlignShape`, `AlignMolecule`, `ScoreShape`, `TransformConformer` | `PubChemShape.cpp` | official wheel's `rdShapeAlign` on `test1.sdf` and more pairs |
| S4 Python `rdoxide.Chem.rdShapeAlign` | `Wrap/cshapealign.cpp`, `ShapeInputOptions`, `FloatVector` | upstream `test_rdshapealign.py` in the ratchet |

Licence file to add with S1: `LICENSES/PubChemAlign3D-PublicDomain.txt` (the NCBI notice).

## Status

* S1+S2 done: `external::pubchem_shape::{consts, functions, neighbor}`. 115 pairs of molecules (with and without hydrogens,
  colour on/off, 4-pose and 16-pose starts) give the same volumes, steric frame classes, matrices and Tanimotos as the C++
  library bit for bit on macOS (`tests/data/pubchem_shape_align.txt`, `tools/pcshape_drv/align.cpp`,
  `tools/make_pubchem_shape_corpus.py`; the constant tables are generated by `tools/gen_pubchem_shape_consts.py`).
  Upstream quirk kept: one `memcpy` copies `7 * sizeof(float)` bytes of a `double[7]` (3.5 doubles).
  Corpus gaps: perturbing that copy, the `line_iter > 3` limit or the 0.7 pose filter does not change any result.
  Deliberately different: the C++ returns an uninitialized pose when no starting pose scores above zero (shapes without
  volume atoms); here it is the zero quaternion.

## Status: S3 + S4 done

`shape.rs` (shape preparation, alignment, scoring, conformer transform) and the Python module
`rdoxide.Chem.rdShapeAlign` are in. Against the official wheel, `AlignMol`/`AlignShapes` agree to ~1e-14
for default settings. Upstream `test_rdshapealign.py`: 7/9 pass. `test1_Defaults` and `test3_FromShape`
(`max_preiters=3`, `opt_param=0.5`) differ in the colour score by 1e-3: the pose after so few pre-iterations is
sensitive to floating-point contraction (the wheel is compiled with FMA contraction, the oracle for the bit-exact
corpus is not), so they stay out of the ratchet.
